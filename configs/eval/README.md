# Evaluation recipes and source inventory

`quick.yaml` configures original EN/RU arithmetic, choice, LM and bounded-code
controls. `scripts/evaluation_suite_smoke.py` resolves exact EvalJob recipes against
actual checkpoint/tokenizer/dataset manifests. `benchmarks.yaml` is generated by
`qvelt eval-registry`; `--check` rejects a stale inventory.

Protocol `qvelt-eval-v2` uses the native cached engine, explicit stop reasons,
versioned answer extraction, character-normalized choice likelihood, Wilson
intervals, unbiased pass@k and first-seen-tie majority@k. The legacy v1 digest and
frozen final holdout are preserved. This suite never silently enables final scoring.

Approved public imports are bounded zero-shot GSM8K test and MMLU abstract-algebra and ARC-Challenge
test subsets. They differ from official full/five-shot protocols and are not
headline benchmark scores. MATH/MATH-500, AMC/AIME, HellaSwag and full HumanEval
remain blocked by the specific rights/access/execution gates in the registry.
Original bounded expression tests are HumanEval-style controls, not HumanEval.

A complete native report includes predictions, exact metrics, lexical audit, input
manifest snapshots, resolved model/evaluation configs, evaluator source/environment
provenance and a reproduction command. Public receipts exclude raw corpus text and
weights. `qvelt results` verifies receipts before generating the root results ledger.
See [the runbook](../../runbooks/04_evaluation.md).

Production training exclusion coverage remains separately enforced by
`qvelt.data.decontamination.MANDATORY_BENCHMARKS`. Partial evaluation approval does
not unblock production source selection or establish complete training history.
